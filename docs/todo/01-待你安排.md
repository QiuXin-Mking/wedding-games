### 5. ~~婚礼题库 **16 道**~~ · ✅ **已完成**（2026-09-22）

已入库 `questions/wedding.json`（13 正 + 3 备），已随代码部署到服务器，启动校验通过。
正式场前记得切过去，见第 10 条。下面的格式说明留作以后改题时参考。


**做什么**：新人提供 **13 道正题 + 3 道备用题**。

备用题是给主持人救场用的：某道题念错了或有歧义，就换一道备用题重来
（不能重答原题 —— 答案刚在大屏上公布过，重答等于集体送分）。

**格式**（照 `questions/test.json` 填，`answer` 是正确选项的下标，从 0 开始）：
```json
[
  { "text": "新郎新娘是在哪里认识的？",
    "options": ["大学社团", "同事介绍", "旅行途中", "相亲"], "answer": 1 },
  { "text": "（第 14~16 条是备用题，加 spare 标记）",
    "options": ["甲", "乙"], "answer": 0, "spare": true }
]
```

**约束**：
- 正题必须**恰好 13 道**，备用题**至少 1 道**（建议 3 道）
- 每题至少 2 个选项；判断题就写「对 / 错」两个选项
- **纯文字，不能有图片**
- 题干别太长 —— 20 秒要读完题干和四个选项

填好存成 `questions/wedding.json`，服务端启动时会自动校验，
**格式不对会直接启动失败并指出是第几条的什么问题**，不会带着坏数据开场。

> 对应 RISK-5 / AC-16 / AC-17

### 7. 纸质题卡（含答案）· **仍然要**，但理由变了

**做什么**：把 16 道题连同正确答案打印一份，交给主持人。

**怎么生成**：`npm run cards`，生成 `wip/题卡.html`，浏览器打开后 Ctrl+P 打印（A4，正确答案已加粗标出，备用题单独一节）。

**原来的理由已失效**：它本来是为「服务器挂了 → 转口头抢答」准备的，
而该预案在 2026-09-22 取消了（挂了就直接下个节目）。

**现在的理由有两条**：

1. **主持人要提前熟悉题目。** 他得把题目和四个选项完整念一遍再按「下一题」，
   照着屏幕现场读和事先看过是两回事 —— 尤其题目全是关于新人的，
   念到某些内容时他可能想临场补一句，那需要提前知道。
2. **控制台临时打不开时能继续念题。** 平板没电、锁屏、误关标签页都可能发生，
   换备用设备要几十秒；这期间**游戏其实还活着** —— 宾客手机上有题、分数照常算，
   主持人只要能念出题目，全场就不会停。

> 对应 AC-59

### 9. 与主持人交底，并让他**独立**跑通一遍

**做什么**：
- 把控制台交给主持人，讲一遍
- 然后**你不说话**，让他自己从「开始游戏」跑到「公布排行」
- 中途让他试一次「跳过本题」和「换一道备用题」

**验收线是「他能独立跑通」**，不是「他听懂了」。
文档写得再好，主持人现场不敢点按钮就等于没做。

**要特别跟他说清的两件事**：
1. **先念完题再点「下一题」** —— 点下去倒计时立刻开始走
2. 喊完「大家扫码」之后，**要有约 8 秒的垫场话** ——
   400 人同时扫码，页面加载需要这么久（1 秒内会先出「正在进入」，不会白屏）

> 对应 AC-36 / AC-39
